## 包与部署

- [ ] 源码 ZIP 与部署 ZIP 校验值匹配 SHA256SUMS.txt。
- [ ] ZIP 不含 `.private`、`.env`、真实 Secret/Token、原内网密码、日志、CSV 或 node_modules。
- [ ] Node.js 24 LTS；运行时依赖安装成功；`npm start` 成功；单实例。
- [ ] HTTPS、正确域名、仓库外只读配置挂载已验证；浏览器不出现 Secret。
- [ ] 负责人直接在服务器受限配置文件填入 Secret；没有通过代码包、聊天或日志传递。
- [ ] 自动监控不记录 OAuth 完整 URL、Cookie、令牌、请求体或报表内容。

## 身份与权限（必须使用实际 Shopify 账号验收）

- [ ] 未登录访问 `/api/dashboard` 返回 401，不返回报表。
- [ ] 不配置任何员工名单，任一家指定店铺的有效报表员工均可登录。
- [ ] 从 Lakeside 或 LTD 登录均可查看和导出双店数据；负责人确认此跨店开放范围。
- [ ] 顾客账号不能冒充员工；修改店铺域名、state、hmac 的回调被拒绝。
- [ ] 退出后旧 Cookie 不可再请求报表；重启后需重新登录。
- [ ] 旧名单为空或缺失不影响有效员工登录；撤销 Shopify 在线令牌后下次请求失败。
- [ ] 即使已登录，`/setup` 和 `/api/local/settings`、`/api/local/verify` 仍为 403。
- [ ] 密码登录接口在云端不可使用；伪造 Host/跨站 POST 被拒绝。
- [ ] Cookie 含 HttpOnly、Secure、SameSite；浏览器资源不含应用 Secret/Token。

## 数据

- [ ] 固定完整日期分别与 Lakeside、LTD 的 Shopify 后台对账（同币种/时区）。
- [ ] 两店合计销售额、净销售额、订单数与单店之和相符；AOV/CR 按分子分母合并。
- [ ] Amazon/Walmart/Target 等渠道可筛选；仅覆盖已同步到 Shopify 的订单，未知渠道不猜测。
- [ ] 临时使测试环境一店配置无效后，合并查询明确报错，不显示缺失店为 0 的新合计；完成后恢复。
- [ ] 日期、平台、商品筛选及 CSV 导出可用；当前日/时区解释符合业务预期。
- [ ] 数据错误时确认提示“上次成功读取”不会被当作最新结果。
